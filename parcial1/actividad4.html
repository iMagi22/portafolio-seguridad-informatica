Práctica: ACTIVIDAD 04 - Mecanismos de defensa en red (iptables)

1. Introducción Contextual

En el panorama actual de ciberseguridad, el firewall actúa como la primera línea de defensa. Esta actividad se centra en la implementación de un Firewall de Filtrado de Paquetes utilizando iptables en Linux, bajo una estrategia de "Denegación Implícita", donde solo el tráfico estrictamente necesario es permitido.

2. Desarrollo Técnico: Implementación de Reglas

Se configuró el sistema para proteger una red local (192.1.2.0/24) y servidores específicos de correo y web.

# 1. Política Restrictiva
iptables -P INPUT DROP
iptables -P FORWARD DROP

# 2. Permitir DNS Saliente
iptables -A OUTPUT -p tcp --dport 53 -s 192.1.2.0/24 -j ACCEPT

Captura simulada de implementación de políticas de seguridad.

Listado de Políticas Aplicadas:

  • Tráfico de Estado: Se permite el flujo de conexiones ya establecidas para no interrumpir sesiones legítimas.
  • Servidor de Correo (SMTP): Apertura del puerto 25 exclusivamente para la IP del servidor 192.1.2.10.
  • Acceso Web: Los usuarios locales pueden navegar (Puerto 80) y el servidor institucional puede recibir peticiones externas.

3. Opinión y Reflexión Técnica

La implementación de una "Lista Blanca" (White Listing) mediante iptables -P DROP es, en mi opinión, la medida más efectiva para reducir la superficie de ataque de una organización. En escenarios reales, esto evita que un malware que haya infectado un equipo interno pueda comunicarse con su servidor de Comando y Control (C2) por puertos no autorizados. Esta práctica refuerza el principio de defensa en profundidad, limitando el movimiento lateral del atacante.
