Parte 01 — Comprensión del Modelo Diamante

El Modelo Diamante de Intrusión es un marco analítico de threat intelligence que representa cada evento de intrusión como la interacción de cuatro vértices fundamentales que definen la naturaleza, el origen y el impacto de un ataque cibernético.

// TABLA CONCEPTUAL — 4 ELEMENTOS

ELEMENTODESCRIPCIÓNEJEMPLO PRÁCTICO
ADVERSARIO Actor de amenaza — individuo o grupo responsable de dirigir y ejecutar la intrusión cibernética para alcanzar un objetivo específico (financiero, espionaje, sabotaje). Grupo tipo APT (Amenaza Persistente Avanzada) o atacante externo (Red Team / Black Hat) motivado por la exfiltración de información confidencial.
CAPACIDAD Conjunto de herramientas, técnicas, tácticas y procedimientos (TTPs) desarrollados o adquiridos que el adversario utiliza para llevar a cabo la intrusión. Desarrollo de un payload malicioso o uso de SQL Injection para extracción de registros en base de datos.
INFRAESTRUCTURA Estructura física y/o lógica (IPs, dominios, servidores, redes) empleada por el adversario para controlar capacidades, enviar malware y mantener comunicación C2. Servidor privado virtual (VPS) como servidor de Comando y Control (C2), junto con dominios ofuscados para campañas de phishing.
VÍCTIMA Objetivo principal del ataque: persona, organización, servidor de red, activo de información o dirección de correo específica comprometida por el adversario. Servidor de bases de datos interno o credenciales de acceso de un administrador de sistemas dentro de la organización afectada.

// ANÁLISIS DETALLADO — 5 PUNTOS CLAVE

PUNTO 1Adversario
¿Quién es el adversario?
Actor de amenaza externo rastreado mediante herramientas de WHOIS/IP. Capacidad de registrar dominios específicos y gestionar servidores de control — perfil consistente con un grupo APT.
PUNTO 2Capacidad
¿Cuál es la capacidad utilizada?
Variante de malware con funciones avanzadas: evasión de detecciones, consultas DNS para resolver dominios C2 y conexiones persistentes hacia el exterior para recibir instrucciones.
PUNTO 3Infraest.
¿Qué tipo de infraestructura se emplea?
Infraestructura híbrida: dominios registrados específicamente para el ataque + IPs externas como nodos de terminación C2. Permite interacción con sistemas comprometidos sin exposición directa del adversario.
PUNTO 4Víctima
¿Quién es la víctima primaria?
La organización afectada — equipos y terminales de red donde se detectó el comportamiento anómalo. Impacto centralizado en los activos de información internos como punto de entrada.
PUNTO 5Mov. Lateral
¿Existe evidencia de movimiento lateral?
SÍ — evidencia clara. Los logs mostraron que múltiples hosts internos intentaban establecer conexiones hacia las mismas IPs externas, indicando distribución del compromiso en la red local.

Conclusión y Reflexión Técnica

// APORTACIÓN DEL MODELO DIAMANTE AL ANÁLISIS

El Modelo Diamante demostró su valor como framework de threat intelligence al estructurar un incidente complejo en cuatro vértices claramente definidos. Su mayor fortaleza fue revelar la transición de roles: la Víctima 1 dejó de ser solo un objetivo para convertirse en parte de la infraestructura del adversario — un insight que los modelos tradicionales de análisis de logs difícilmente capturan. La correlación de los dos hilos de actividad confirmó que se trataba de una campaña APT coordinada, no de dos incidentes aislados.

// KILL CHAIN + MODELO DIAMANTE — INTEGRACIÓN PROFESIONAL

La combinación de ambos modelos proporcionó una visión completa: mientras la Kill Chain define el cuándo (fase táctica), el Modelo Diamante define el quién, con qué, cómo y contra quién. Esta integración es el estándar en operaciones de Threat Intelligence en entornos SOC y equipos CSIRT. La detección del beaconing DNS y el análisis WHOIS representan técnicas reales de atribución en investigaciones de nivel avanzado.
