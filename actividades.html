Actividad 01: Análisis de NotPetya - Maersk (2017)

Introducción: NotPetya fue un malware destructivo disfrazado de ransomware que atacó a través del software contable M.E.Doc. Maersk fue una de las entidades más afectadas globalmente.

Evaluación del Impacto (Modelo CIA)

DimensiónImpacto
ConfidencialidadBajo. El objetivo no era el robo de datos, sino la destrucción, aunque se comprometieron credenciales locales.
IntegridadAlto. El malware sobrescribió el MBR y cifró la tabla maestra de archivos (MFT) de forma irreversible.
DisponibilidadCrítico. Suspensión total de operaciones portuarias y logísticas en 76 terminales a nivel mundial.

Costo Económico Estimado

  • Interrupción de ingresos: $250 - $300 millones de USD.
  • Recuperación tecnológica: Reinstalación de 4,000 servidores y 45,000 computadoras.

Actividad 02: Servicios de Seguridad (X.800 y RFC 4949)

Análisis Conceptual: Integración del modelo arquitectónico X.800 y el glosario técnico RFC 4949 para el análisis de incidentes.

Escenarios de Seguridad

  • Audit Trail: Registros cronológicos que permiten reconstruir eventos de seguridad.
  • Masquerade: Ataque donde una entidad finge ser otra (ej. Phishing institucional).
  • No Repudio: Garantiza que el emisor de un mensaje no pueda negar su autoría.
  • Integridad Probatoria: Asegura que los logs no fueron alterados tras un ataque.

Actividad 03: Iptables - Traducción de Políticas

Tablas de Netfilter:

FILTER (Filtrado), NAT (Traducción de direcciones), MANGLE (Modificación de paquetes).

Anatomía de Regla Crítica:

iptables -A INPUT -i eth0 -p tcp -m multiport --dports 22,80,443 -m state --state NEW,ESTABLISHED -j ACCEPT

Interpretación: Esta regla habilita un servidor web seguro permitiendo tráfico entrante por la interfaz eth0 hacia los puertos 22 (SSH), 80 (HTTP) y 443 (HTTPS) solo para conexiones nuevas o ya establecidas bajo el protocolo TCP.

Actividad 04: Mecanismos de Defensa en Red

Script de Firewall Restrictivo:

  1. Política por defecto: iptables -P INPUT DROP / -P FORWARD DROP
  2. DNS Local: Permitir puerto 53 (UDP/TCP) desde 192.1.2.0/24 hacia el exterior.
  3. Servidor de Correo (IP 192.1.2.10): Permitir puerto 25 (SMTP) entrante y saliente.
  4. Servidor Web (IP 192.1.2.11): Permitir puerto 80 (HTTP) entrante desde cualquier origen.
